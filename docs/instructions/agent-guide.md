# Agent Guide для Checko MCP

Внутренний справочник для AI-агента: правила, поля, анти-паттерны при работе с Checko.ru API через этот MCP-сервер.

> Этот документ доступен через MCP как ресурс `checko://docs/agent-guide`.
> Сервер также экспонирует другие справочники и готовые сценарии — см. конец документа.

---

## Доступные инструменты

Инструменты трёхуровневые: сначала найти субъекта, потом получить отчёт, и только при необходимости — копать по отдельным реестрам.

**Уровень 1 — вход**

| Инструмент | Когда применить | Обязательные параметры |
|---|---|---|
| `resolve` | Есть только наименование, ФИО или непонятный набор цифр. Возвращает короткий список кандидатов с идентификаторами | `query` |
| `profile` | Есть идентификатор, нужна полная карточка. Вид субъекта и метод API определяются автоматически по числу цифр | `identifier` |

**Уровень 2 — готовые отчёты, один вызов вместо шести**

| Инструмент | Что делает | Цена |
|---|---|---|
| `due_diligence_report` | Полная проверка контрагента: карточка, финансы, активные иски-ответчик, ФССП, Федресурс, ЕФРСБ. Считает сигналы | 5–6 запросов |
| `bankruptcy_risk` | Риск банкротства по четырём источникам: ЕФРСБ, намерения кредиторов, ФССП, капитал 1300 | 4–5 запросов |

Начинай с отчёта, а не с ручной сборки. Отдельные инструменты нужны, когда отчёт показал проблему и надо посмотреть детали, либо когда вопрос узкий (например, только госзакупки).

**Уровень 3 — отдельные реестры**

| Инструмент | Когда применить | Обязательные параметры |
|---|---|---|
| `get_finances` | Финансовая отчётность (Росстат, ГИР БО ФНС, 2011+) | `ogrn` или `inn` |
| `get_legal_cases` | Арбитражные дела с фильтрами | `ogrn` или `inn` |
| `get_contracts` | Госзакупки по ОДНОМУ закону за вызов | `ogrn`/`inn` + **`law=44`, `94` или `223`** |
| `get_inspections` | Проверки | `ogrn` или `inn` |
| `get_enforcements` | **Исполнительные производства ФССП** — долги на взыскании | `ogrn` или `inn` |
| `get_bank` | Сведения о банке по БИК | `bic` (9 цифр) |
| `get_timeline` | Хронология изменений | `ogrn` или `inn` |
| `get_fedresurs` | Сообщения Федресурса | `ogrn` или `inn` |
| `get_bankruptcy_messages` | Записи ЕФРСБ | `ogrn` или `inn` |

Идентификаторы: ОКПО — 8 цифр, БИК банка — 9, ИНН юрлица — 10, ИНН физлица и ИП — 12, ОГРН организации — 13, ОГРНИП предпринимателя — 15. `resolve` и `profile` определяют вид субъекта по длине сами, угадывать метод не нужно. Инструменты уровня 3, работающие и с организациями, и с ИП (`get_legal_cases`, `get_contracts`, `get_inspections`, `get_enforcements`, `get_timeline`, `get_fedresurs`, `get_bankruptcy_messages`), принимают ОГРН/ОГРНИП в `ogrn` и любой ИНН в `inn`.

ИНН из 12 цифр неоднозначен: это может быть ИП, а может быть физлицо без ИП. `profile` сначала проверяет ЕГРИП и только при отсутствии ИП обращается к данным физлица — то есть переход к персональным данным происходит осознанно и отражается в ответе.

**Данные по Беларуси недоступны.** У портала Checko есть реестр ЕГР Минюста РБ с идентификатором УНП, но в API его нет — ни один метод не принимает УНП. На вопрос о белорусской компании скажи об этом прямо, не подставляй УНП в `inn`.

## Готовые сценарии — используй prompts

Если задача типовая, **не строй pipeline руками** — вызови подходящий prompt. В нём уже зашит правильный порядок инструментов и шаблон финального ответа.

| Prompt | Когда |
|---|---|
| `check_counterparty(query, purpose?)` | Комплексная проверка контрагента перед сделкой |
| `verify_bank_details(inn, bic)` | Проверка платёжных реквизитов перед оплатой |
| `assess_bankruptcy_risk(inn, context?)` | Оценка вероятности банкротства |
| `audit_person(inn, purpose?)` | Полный аудит физлица по методологии |
| `evaluate_tender_participant(query, purpose?)` | Оценка участника тендера |
| `analyze_finances(ogrn_or_inn, years?)` | Анализ финансовой динамики компании |

К ручному pipeline прибегай только если задача нестандартная или комбинирует несколько сценариев.

## Базовые правила

1. **ОГРН лучше ИНН.** ОГРН уникален всегда. ИНН юрлица может совпадать у головной организации и филиалов — API вернёт головную.
2. **По ФИО ищи через `resolve`.** `profile` принимает только идентификатор. Но если известно имя, `resolve(by="founder-name", query="фамилия имя отчество")` вернёт организации, где человек указан учредителем, а `by="leader-name"` — где он руководитель. Это основной способ раскрутить связи человека, не зная его ИНН; сужай выдачу параметром `region`. Однофамильцы неизбежны — сверяй найденное с другими признаками, прежде чем утверждать, что это тот же человек.
3. **`profile` с ИНН физлица возвращает РЕАЛЬНЫЕ персональные данные.** Подтверди законное основание ДО вызова (152-ФЗ, см. `checko://docs/legal`). Не подставляй «случайные» 12 цифр для проверки работоспособности — ответ может содержать ФИО и связи реального человека. Для проверки берите синтетические идентификаторы, которые API отклонит.
4. **Не ищи то, что уже известно.** Если ОГРН или ИНН на руках — сразу `profile` или отчёт, `resolve` для этого не нужен (он и сам распознает цифры и не пойдёт в поиск). Минимум 4 символа для поиска по наименованию или ФИО. По наименованию отдаётся не больше 100 результатов, отсортированных по релевантности.
5. **`get_contracts` — один закон за вызов.** Параметр `law` обязателен (`44`, `94` или `223`). Чтобы получить полную картину — делай несколько вызовов и объединяй результаты. `sort="-price"` сразу показывает крупнейшие контракты — это быстрее, чем выгружать все страницы.
6. **`get_finances` для банков и страховых обычно пуст.** Они сдают отчётность по другим формам (банковская/страховая), а не по бухгалтерскому балансу — `get_finances` вернёт почти все нули. Для финансового анализа банка используй данные ЦБ РФ, не Checko.
7. **Следи за квотой правильно.** В каждом ответе есть `meta.today_request_count` (запросов за сутки) и `meta.balance` (платный остаток, руб.). Ориентируйся на **счётчик запросов**: бесплатный тариф даёт 100 запросов в сутки, и на нём `meta.balance` равен 0 постоянно — сам по себе нулевой баланс ни о чём не говорит и пугать им пользователя не надо. Предупреждай, когда счётчик подходит к 100. Ошибки валидации на стороне API запрос не списывают.
8. **Ответы приходят сжатыми.** По умолчанию `detail="compact"`: длинные списки урезаны, сводные показатели сохранены, а в блоке `сжатие` указано, сколько элементов было всего. Это сделано намеренно — полные ответы доходят до 150 000 символов и обрезаются MCP-клиентом молча. Запрашивай `detail="full"` только когда действительно нужны все записи, и лучше вместе с фильтрами или `limit`.

## Как читать ответ

### Общий блок `meta`

| Поле | Смысл |
|------|-------|
| `meta.status` | `"ok"` или `"error"` (при `error` — текст в `meta.message`) |
| `meta.balance` | Остаток баланса, руб. |
| `meta.today_request_count` | Счётчик запросов за сегодня |

### `profile` — ключевые поля карточки организации и ИП

| Поле | Что в нём |
|------|-----------|
| `data.НаимПолн`, `data.НаимСокр` | Полное и сокращённое наименование |
| `data.Статус.Наим` | "Действует" / "Ликвидирована" — критичный фильтр |
| `data.Статус.Дата` | Дата изменения статуса |
| `data.Руковод[]` | Массив руководителей (обычно 1; >1 = несколько ЕИО, редкий случай) |
| `data.Учред.ФЛ[]` / `.РосОрг[]` / `.ИнОрг[]` / `.ПИФ[]` / `.РФ[]` | Учредители: физлица / российские организации / иностранные организации / ПИФы / государство |
| `data.СвязУчред[]` | Компании, связанные через учредителей |
| `data.Лиценз[]` | Лицензии — для проверки права на лицензируемую деятельность |
| `data.РМСП` | Реестр МСП (у крупных организаций пустой) |
| `data.Налоги` | Налоговые сведения (у части организаций пустой) |
| `data.Обрем[]` | Обременения: залоги, аресты — блок появляется не у всех |
| `data.ОКВЭД`, `data.ОКВЭДДоп[]` | Основной и дополнительные коды видов деятельности |
| `data.Подразд.Филиал[]` | Филиалы |
| `data.УстКап` | Уставный капитал: `Тип`, `Сумма` |
| `data.Контакты` | Телефоны, email, сайт |

Флаги риска — скалярные поля верхнего уровня: `Санкции`, `СанкцУчр`, `СанкцииСтраны[]`, `НелегалФин`, `НедобПост`, `ДисквЛица`, `МассРуковод`, `МассУчред`, `ЕФРСБ[]`. Дополнительно: `ЮрАдрес.Недост`, `ЮрАдрес.МассАдрес`, а внутри `Руковод[]` — `Недост`, `МассРуковод`, `ДисквЛицо`.

### `get_finances` — ключевые строки отчётности

При `extended=true` доступны строки бухбаланса (ф.0710001) и ОФР (ф.0710002):

| Строка | Что | Сигнал |
|--------|-----|--------|
| `2110` | Выручка | Динамика выручки — рост/падение |
| `2400` | Чистая прибыль (убыток) | Знак и динамика |
| `1300` | Капитал и резервы | **Отрицательный → банкротство близко** |
| `1400` | Долгосрочные обязательства | Долговая нагрузка |
| `1500` | Краткосрочные обязательства | Текущие долги |
| `1600` | Баланс активов | Размер бизнеса |

Данные за последний завершённый год часто отсутствуют — ГИР БО публикует с задержкой ~6 мес.

### `get_legal_cases` — фильтры обязательны

- `Записи[]` — каждое дело: `Номер`, `Дата`, `Тип`, `Суд`, `Ист` (истец), `Ответ` (ответчик), `СуммИск`, `ПрАктуал`, `ПрАктив`, `СтрКАД` (ссылка на карточку дела).
- `ЗапВсего` — сколько дел найдено всего, `ОбщСуммИск` — суммарная цена иска. Этих двух чисел обычно достаточно, выгружать все записи не нужно.
- **Без `actual=true` придёт шум** (отклонённые и прекращённые дела). Всегда указывай `actual=true`, если не нужен исторический срез.
- **Без `active=true`** возвращаются и закрытые дела.
- Для оценки рисков обычно нужно: `actual=true, active=true, role="defendant"`.

### `get_fedresurs` — самые важные типы сообщений

| `type` | Смысл | Серьёзность |
|--------|-------|:-----------:|
| `CreditorIntentionGoToCourt` | Кредитор уведомил о намерении подать на банкротство | 🔴 |
| `BankruptcyMessage` | Публикация в рамках банкротного дела | 🔴 |
| `PledgeAgreement` | Договор залога имущества | 🟡 |
| `LeaseAgreement` | Договор лизинга | 🟢 (информативно) |

## Факторы риска (приоритизированы)

| Поле | Серьёзность | Что означает |
|------|:-----------:|--------------|
| `Санкции: true` | 🔴 | Включён в санкционные списки. Регуляторный риск; нужна правовая оценка. |
| `НелегалФин: true` | 🔴 | Признаки нелегальной финансовой деятельности (ЦБ РФ) |
| `Статус: "Ликвидирована"` | 🔴 | Сделки невозможны |
| Записи `ЕФРСБ` непустые | 🔴 | Открыта банкротная процедура |
| `get_enforcements` вернул открытые производства | 🟠 | Долг уже взыскивается приставами: решение вступило в силу и не исполнено. Сильнее иска — иск это лишь требование |
| `НедобПост: true` | 🟠 | В реестре недобросовестных поставщиков (ФАС) |
| Капитал (`1300`) отрицательный | 🟠 | Технические признаки банкротства |
| `МассРуковод: true` | 🟡 | Руководитель числится массовым (>5 компаний — фон ФНС) |
| `МассУчред: true` | 🟡 | Учредитель числится массовым |
| `МассАдрес: true` | 🟡 | Адрес массовой регистрации |
| `Обрем` непустой | 🟡 | Имущество в залоге/аресте |

## Анти-паттерны — что НЕ делать

- ❌ **Звать `profile` с произвольным 12-значным числом «просто чтобы проверить».** API вернёт реальные ПД любого существующего ИНН — это передача персональных данных без основания. Только при явном запросе пользователя и наличии законного основания (см. `checko://docs/legal`).
- ❌ **Собирать проверку контрагента вручную из шести инструментов.** Для этого есть `due_diligence_report`: он делает те же запросы параллельно, считает сигналы и не даёт забыть про исполнительные производства. Ручная сборка нужна только для узких вопросов.
- ❌ **`get_contracts` без `law`.** API упадёт с HTTP 400. Если нужны разные законы — делай отдельные вызовы.
- ❌ **`source=true` без необходимости.** Это полный дамп данных ЕГРЮЛ от ФНС: ответ раздувается настолько, что MCP-клиент может его обрезать, и ты получишь неполный JSON, не заметив этого. Включай только когда нужного поля точно нет в обычном ответе.
- ❌ **Считать, что иск и исполнительное производство — одно и то же.** Иск (`get_legal_cases`) — заявленное требование, его могут отклонить. Исполнительное производство (`get_enforcements`) — уже вступившее в силу решение, которое не исполнено. Про платёжную дисциплину говорит второе.
- ❌ **Подставлять белорусский УНП в `inn`.** В API нет белорусских данных: ответ будет пустым или ошибочным, а не «компания не найдена».
- ❌ **Делать выводы о финансах банка по `get_finances`.** Для банков таблица почти всегда из нулей (банковская отчётность отдельная — формы 0409xxx ЦБ РФ). Используй другие источники.
- ❌ **Пугать пользователя нулевым `meta.balance`.** На бесплатном тарифе он равен 0 всегда, и 100 запросов в сутки при этом работают. Смотри на `meta.today_request_count`.
- ❌ **Считать пустой ответ доказательством отсутствия компании.** На белорусский УНП API отвечает `200` с пустым `data`, а не ошибкой — это выглядит как «не найдено», хотя на самом деле такой поиск не поддерживается.
- ❌ **`get_legal_cases` без `actual=true`** при вопросе про активные иски — пользователь утонет в шуме закрытых.
- ❌ **`profile` по ИНН для крупного холдинга, если можешь получить ОГРН.** При филиалах ИНН не уникален — API вернёт головную организацию, и пользователь может этого не понять.
- ❌ **Полагаться на свежесть арбитражных дел.** Задержка обновления — 1–2 недели.
- ❌ **Массовый сбор данных физлиц.** Прямо нарушает 152-ФЗ — см. `checko://docs/legal`.
- ❌ **Решение об оплате/сделке только по статусу.** "Действует" ≠ финансовое здоровье. Проверяй финансы и иски.
- ❌ **Выводы из одного периода `get_finances`.** Запрашивай несколько лет, смотри динамику.
- ❌ **Считать отсутствие записей в Федресурсе/ЕФРСБ за «всё чисто».** Иногда процедуры только начинаются и публикации запаздывают на дни-недели.

## Ограничения API

- Финансовая отчётность доступна с 2011 года.
- Данные физлица доступны только по ИНН; ФИО ищется через `resolve` с `by="founder-name"` или `by="leader-name"`.
- Белорусских данных (УНП) в API нет — только российские реестры.
- Бесплатный тариф — 100 запросов в сутки. Каждый вызов инструмента расходует один запрос, поэтому не запрашивай то, что уже получил.
- `limit` — не больше 100 записей на страницу у всех методов с постраничным выводом.
- Все суммы — в рублях.
- Даты — `YYYY-MM-DD`.
- Кодировка ответов — UTF-8.
- Текущая версия API — **2.4** (02.2026): добавлены `/timeline`, `/fedresurs`, `/bankruptcy-messages`, `СвязУчред` в `/company`, `codes=all` в `/search`.
