# Agent Guide для Checko MCP

Внутренний справочник для AI-агента: правила, поля, анти-паттерны при работе с Checko.ru API через этот MCP-сервер.

> Этот документ доступен через MCP как ресурс `checko://docs/agent-guide`.
> Сервер также экспонирует другие справочники и готовые сценарии — см. конец документа.

---

## Доступные инструменты

| Инструмент | Когда применить | Обязательные параметры |
|---|---|---|
| `search` | Найти юрлицо, когда есть только название или код деятельности | `by` (`name`/`okved`), `obj=org`, `query` |
| `get_company` | Полные данные ЕГРЮЛ по юрлицу | `ogrn` или `inn` |
| `get_entrepreneur` | Полные данные ЕГРИП по ИП | `ogrnip`, `inn` или `okpo` |
| `get_person` | Связи и риски физлица | `inn` (12 цифр) |
| `get_finances` | Финансовая отчётность (Росстат, ГИР БО ФНС, 2011+) | `ogrn` или `inn` |
| `get_legal_cases` | Арбитражные дела с фильтрами | `ogrn` или `inn` |
| `get_contracts` | Госконтракты по ОДНОМУ закону за вызов | `ogrn`/`inn` + **`law=44` или `223`** |
| `get_inspections` | Проверки | `ogrn` или `inn` |
| `get_bank` | Сведения о банке по БИК | `bic` (9 цифр) |
| `get_timeline` | Хронология изменений (v2.4) | `ogrn` или `inn` |
| `get_fedresurs` | Сообщения Федресурса (v2.4) | `ogrn` или `inn` |
| `get_bankruptcy_messages` | Записи ЕФРСБ (v2.4) | `ogrn` или `inn` |

## Готовые сценарии — используй prompts

Если задача типовая, **не строй pipeline руками** — вызови подходящий prompt. В нём уже зашит правильный порядок инструментов и шаблон финального ответа.

| Prompt | Когда |
|---|---|
| `check_counterparty(query, purpose?)` | Комплексная проверка контрагента перед сделкой |
| `verify_bank_details(inn, bic)` | Проверка платёжных реквизитов перед оплатой |
| `assess_bankruptcy_risk(inn, context?)` | Оценка вероятности банкротства |
| `audit_person(inn, purpose?)` | Полный аудит физлица по методологии |
| `evaluate_tender_participant(query, purpose?)` | Оценка участника тендера |
| `analyze_finances(ogrn_or_inn, years?)` | Анализ финансовой динамики компании |

К ручному pipeline прибегай только если задача нестандартная или комбинирует несколько сценариев.

## Базовые правила

1. **ОГРН лучше ИНН.** ОГРН уникален всегда. ИНН юрлица может совпадать у головной организации и филиалов — API вернёт головную.
2. **Физлицо — только по ИНН (12 цифр).** Поиск по ФИО не поддерживается. Если у пользователя только имя — нужен альтернативный источник, чтобы найти ИНН.
3. **`get_person` возвращает РЕАЛЬНЫЕ ПД любого валидного ИНН.** Подтверди законное основание ДО вызова (152-ФЗ, см. `checko://docs/legal`). Не подставляй «случайные» 12 цифр для теста — ответ может содержать ФИО, СНИЛС-следы и связи реального человека. Для тестирования используй mock-сценарии или synthetic-INN, который провалит вызов на стороне API.
4. **`search` — только текстовый поиск.** Чтобы получить юрлицо по уже известному ОГРН/ИНН — сразу зови `get_company`, не `search`.
5. **`get_contracts` — один закон за вызов.** Параметр `law` обязателен (`44` или `223`). Чтобы получить полную картину — делай два вызова и объединяй результаты.
6. **`get_finances` для банков и страховых обычно пуст.** Они сдают отчётность по другим формам (банковская/страховая), а не по бухгалтерскому балансу — `get_finances` вернёт почти все нули. Для финансового анализа банка используй данные ЦБ РФ, не Checko.
7. **Следи за квотой.** В каждом ответе `meta.balance` (остаток в рублях) и `meta.today_request_count`. При балансе < 100 руб — предупреди пользователя в начале ответа; при 0 — следующий вызов упадёт с ошибкой. **Ошибки HTTP 400 (валидация на стороне API) баланс не списывают.**

## Как читать ответ

### Общий блок `meta`

| Поле | Смысл |
|------|-------|
| `meta.status` | `"ok"` или `"error"` (при `error` — текст в `meta.message`) |
| `meta.balance` | Остаток баланса, руб. |
| `meta.today_request_count` | Счётчик запросов за сегодня |

### `get_company` / `get_entrepreneur` — ключевые поля

| Поле | Что в нём |
|------|-----------|
| `data.НаимПолн`, `data.НаимСокр` | Полное и сокращённое наименование |
| `data.Статус.Наим` | "Действует" / "Ликвидирована" — критичный фильтр |
| `data.Статус.Дата` | Дата изменения статуса |
| `data.Руковод[]` | Массив руководителей (обычно 1; >1 = несколько ЕИО, редкий случай) |
| `data.Учред.ФЛ[]` / `data.Учред.ЮЛ[]` / `data.Учред.РФ[]` | Учредители: физлица / юрлица / государство |
| `data.СвязУчред[]` | Связанные через учредителей компании (v2.4) |
| `data.Лиценз[]` | Лицензии — для проверки права на лицензируемую деятельность |
| `data.МСП.Кат` | "Микро" / "Малое" / "Среднее" |
| `data.Налоги.СумНедоим` | Налоговая задолженность, руб. |
| `data.Обрем[]` | Обременения: залоги, аресты (v2.3) |
| `data.ОКВЭД`, `data.ОКВЭДДоп[]` | Основной и дополнительные коды видов деятельности |

### `get_finances` — ключевые строки отчётности

При `extended=true` доступны строки бухбаланса (ф.0710001) и ОФР (ф.0710002):

| Строка | Что | Сигнал |
|--------|-----|--------|
| `2110` | Выручка | Динамика выручки — рост/падение |
| `2400` | Чистая прибыль (убыток) | Знак и динамика |
| `1300` | Капитал и резервы | **Отрицательный → банкротство близко** |
| `1400` | Долгосрочные обязательства | Долговая нагрузка |
| `1500` | Краткосрочные обязательства | Текущие долги |
| `1600` | Баланс активов | Размер бизнеса |

Данные за последний завершённый год часто отсутствуют — ГИР БО публикует с задержкой ~6 мес.

### `get_legal_cases` — фильтры обязательны

- `СписДел[]` — каждое дело: `НомерДела`, `ДатаПоступ`, `Истец`, `Ответчик`, `СуммИск`, `Стадия`.
- `ОбщСуммИск` — суммарная сумма всех исков (полезная агрегация).
- **Без `actual=true` придёт шум** (отклонённые и прекращённые дела). Всегда указывай `actual=true`, если не нужен исторический срез.
- **Без `active=true`** возвращаются и закрытые дела.
- Для оценки рисков обычно нужно: `actual=true, active=true, role="defendant"`.

### `get_fedresurs` — самые важные типы сообщений

| `type` | Смысл | Серьёзность |
|--------|-------|:-----------:|
| `CreditorIntentionGoToCourt` | Кредитор уведомил о намерении подать на банкротство | 🔴 |
| `BankruptcyMessage` | Публикация в рамках банкротного дела | 🔴 |
| `PledgeAgreement` | Договор залога имущества | 🟡 |
| `LeaseAgreement` | Договор лизинга | 🟢 (информативно) |

## Факторы риска (приоритизированы)

| Поле | Серьёзность | Что означает |
|------|:-----------:|--------------|
| `Санкции: true` | 🔴 | Включён в санкционные списки. Регуляторный риск; нужна правовая оценка. |
| `НелегалФин: true` | 🔴 | Признаки нелегальной финансовой деятельности (ЦБ РФ) |
| `Статус: "Ликвидирована"` | 🔴 | Сделки невозможны |
| Записи `ЕФРСБ` непустые | 🔴 | Открыта банкротная процедура |
| `НедобПост: true` | 🟠 | В реестре недобросовестных поставщиков (ФАС) |
| Капитал (`1300`) отрицательный | 🟠 | Технические признаки банкротства |
| `МассРуковод: true` | 🟡 | Руководитель числится массовым (>5 компаний — фон ФНС) |
| `МассУчред: true` | 🟡 | Учредитель числится массовым |
| `МассАдрес: true` | 🟡 | Адрес массовой регистрации |
| `Обрем` непустой | 🟡 | Имущество в залоге/аресте |

## Анти-паттерны — что НЕ делать

- ❌ **Звать `get_person` «просто чтобы проверить» или с произвольным 12-значным числом.** API вернёт реальные ПД любого существующего ИНН — это передача персональных данных без основания. Только при явном запросе пользователя и наличии законного основания (см. `checko://docs/legal`).
- ❌ **`search` для известного ОГРН/ИНН.** Этот эндпоинт работает только для текстового поиска (`by=name`/`okved`). Если уже есть идентификатор — зови `get_company` напрямую.
- ❌ **`get_contracts` без `law`.** API упадёт с HTTP 400. Если нужны и 44-ФЗ и 223-ФЗ — делай два вызова.
- ❌ **Делать выводы о финансах банка по `get_finances`.** Для банков таблица почти всегда из нулей (банковская отчётность отдельная — формы 0409xxx ЦБ РФ). Используй другие источники.
- ❌ **Игнорировать `meta.balance`.** Если < 100 руб — предупреди в начале ответа. Если 0 — следующий вызов вернёт ошибку.
- ❌ **`get_legal_cases` без `actual=true`** при вопросе про активные иски — пользователь утонет в шуме закрытых.
- ❌ **`get_company(inn=...)` для крупного холдинга, если можешь получить ОГРН.** При филиалах ИНН не уникален — API вернёт головную организацию, и пользователь может этого не понять.
- ❌ **Полагаться на свежесть арбитражных дел.** Задержка обновления — 1–2 недели.
- ❌ **Массовый сбор данных физлиц.** Прямо нарушает 152-ФЗ — см. `checko://docs/legal`.
- ❌ **Решение об оплате/сделке только по статусу.** "Действует" ≠ финансовое здоровье. Проверяй финансы и иски.
- ❌ **Выводы из одного периода `get_finances`.** Запрашивай несколько лет, смотри динамику.
- ❌ **Считать отсутствие записей в Федресурсе/ЕФРСБ за «всё чисто».** Иногда процедуры только начинаются и публикации запаздывают на дни-недели.

## Ограничения API

- Финансовая отчётность доступна с 2011 года.
- Физлицо ищется только по ИНН (12 цифр); ФИО не индексируется.
- Все суммы — в рублях.
- Даты — `YYYY-MM-DD`.
- Кодировка ответов — UTF-8.
- Текущая версия API — **2.4** (02.2026): добавлены `/timeline`, `/fedresurs`, `/bankruptcy-messages`, `СвязУчред` в `/company`, `codes=all` в `/search`.
